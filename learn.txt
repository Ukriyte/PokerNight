1. State machines — highest priority

Understand deeply:

State vs event vs transition
Valid/invalid transitions
Deterministic state transitions
State invariants
Why a poker table should process commands sequentially

You should be able to explain:

State + Command → New State + Events
2. Concurrency

Learn:

Race conditions
Atomicity
Locks
Mutexes
Optimistic vs pessimistic locking
Java synchronized
ReentrantLock
Executors
CompletableFuture
Thread safety

Then understand why your design might use:

1 table → 1 serialized command stream

rather than locking every field.

connection lifecycle

4. Distributed systems fundamentals

This is where the project becomes useful for your career.

Learn:

CAP theorem
consistency
availability
partitioning
replication

distributed locks

What I would NOT spend much time learning

Since Claude is writing the implementation:

React syntax
Spring annotations
WebSocket boilerplate
CSS
CRUD controllers
getters/setters
basic SQL CRUD

You should understand the code, but don't spend weeks memorizing implementation details AI can generate.

Your actual learning target

I'd aim to reach the point where Claude gives you this:

"I implemented per-table serialized command processing."

and you can immediately ask:

"Why does that guarantee ordering? What happens if two WebSocket threads submit simultaneously? What happens if the worker crashes? Where is the command persisted? Is the command idempotent?"

That's the level that will make this project valuable.

A good 3–4 week learning sequence
